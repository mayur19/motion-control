# Motion Badminton Protocol v1

Status: **Frozen for implementation**  
Protocol version: **1**  
Byte order: **network byte order (big-endian)**  
Maximum datagram: **256 bytes**

This document is the complete wire contract between the native phone
controllers and the Godot host. “Must”, “must not”, “should” and “may” are
normative. An implementation must reject data that violates a stated constraint
rather than repairing it silently.

## 1. Encoding conventions

- Unsigned integers use the width shown in each table and big-endian order.
- `f32` is an IEEE 754 binary32 value encoded most-significant byte first.
- All transmitted floating-point values must be finite. NaN and positive or
  negative infinity are invalid. Encoders canonicalize either signed zero to
  positive zero.
- Text is strict UTF-8 without an embedded NUL. Lengths count encoded bytes, not
  Unicode scalar values. No Unicode normalization is performed by the codec.
- Boolean concepts are represented by named integer enums or flag bits, never
  by an undocumented nonzero value.
- Reserved fields and unknown flag bits must be zero when encoding and cause a
  rejection when decoding.
- A timestamp explicitly named `monotonic_ns` is nanoseconds from the sender's
  monotonic clock and is meaningful only within that device boot. It must not
  be derived from wall clock time.

## 2. Common header

Every datagram starts with this 28-byte header.

| Offset | Size | Field | Type | Constraint |
| ---: | ---: | --- | --- | --- |
| 0 | 2 | `magic` | `u16` | Exactly `0x4D42` (ASCII `MB`) |
| 2 | 1 | `protocol_version` | `u8` | Exactly `1` |
| 3 | 1 | `message_type` | `u8` | One value from the message table |
| 4 | 2 | `flags` | `u16` | Only bits 0–1 may be set |
| 6 | 2 | `header_length` | `u16` | Exactly `28` in v1 |
| 8 | 2 | `payload_length` | `u16` | Exact payload bytes following the header |
| 10 | 2 | `reserved` | `u16` | Exactly `0` |
| 12 | 8 | `session_id` | `u64` | Nonzero, generated by the host for one session |
| 20 | 4 | `controller_id` | `u32` | See controller semantics below |
| 24 | 4 | `sequence` | `u32` | Sender-local sequence, modulo 2³² |

The UDP datagram size must equal `header_length + payload_length`; trailing or
missing bytes are invalid. A v1 payload may not exceed 228 bytes, so the whole
datagram never exceeds 256 bytes.

### Header flags

| Bit | Name | Meaning |
| ---: | --- | --- |
| 0 | `ACK_REQUIRED` | Sender expects the corresponding response or a bounded retry |
| 1 | `RETRY` | Same logical request and sequence is being sent again |
| 2–15 | — | Reserved; must be zero |

`MOTION` and `CALIBRATION` must use flags `0`. A retry repeats the original
sequence and payload, sets `RETRY`, and does not create a new logical message.

### Message types

| Value | Name | Direction | Payload size |
| ---: | --- | --- | ---: |
| `1` | `HELLO` | controller → host | 28–153 |
| `2` | `WELCOME` | host → controller | 24 |
| `3` | `PING` | either | 16 |
| `4` | `PONG` | either | 32 |
| `5` | `MOTION` | controller → host | 52 |
| `6` | `CALIBRATION` | controller → host | 56 |
| `7` | `STATUS` | either | 20 |
| `8` | `GOODBYE` | either | 16 |

Unknown message values are rejected; v1 has no extension-message range.

## 3. Identity and sequence semantics

- The host generates a cryptographically random, nonzero `session_id`. It is
  present in the QR payload and unchanged for the session lifetime.
- A joining controller sends `HELLO` with `controller_id = 0`. The host assigns
  a random nonzero ID and returns it in the `WELCOME` header. Every later packet
  for that controller uses the assigned ID.
- The `WELCOME.player` field assigns Player 1 or Player 2. A controller ID and
  player assignment remain stable across reconnect within the host reconnect
  window.
- Each sender/controller direction maintains its own `sequence` counter. It may
  start at any value and increments once for each new logical message. Wrap from
  `0xFFFFFFFF` to `0` is valid.
- Compare sequence numbers using modulo-2³² half-range arithmetic. `a` is newer
  than `b` when `0 < (a - b) mod 2³² < 2³¹`.

## 4. Payloads

Payload offsets below start at byte 0 immediately after the common header.

### 4.1 `HELLO` (type 1)

| Offset | Size | Field | Type | Constraint |
| ---: | ---: | --- | --- | --- |
| 0 | 16 | `pairing_secret` | bytes | Exact secret from QR; not all zero |
| 16 | 1 | `platform` | `u8` | `1` iOS, `2` Android |
| 17 | 1 | `reserved_0` | `u8` | `0` |
| 18 | 2 | `capabilities` | `u16` flags | Defined below; unknown bits zero |
| 20 | 2 | `max_sample_hz` | `u16` | 1–1000 |
| 22 | 1 | `device_model_length` | `u8` | 1–63 |
| 23 | 1 | `app_version_length` | `u8` | 1–31 |
| 24 | 1 | `os_version_length` | `u8` | 1–31 |
| 25 | 3 | `reserved_1` | bytes | All zero |
| 28 | variable | `device_model` | UTF-8 | Exact declared byte length |
| next | variable | `app_version` | UTF-8 | Exact declared byte length |
| next | variable | `os_version` | UTF-8 | Exact declared byte length; ends payload |

Capability bits are: bit 0 accelerometer, bit 1 gyroscope, bit 2 orientation,
bit 3 QR camera and bit 4 sampling above 200 Hz. Bits 0–2 are mandatory for a
Release 1 controller. Bits 5–15 must be zero.

The secret is compared in constant time. A failed secret, expired secret or
already-full session receives a rejection-form `WELCOME` as defined below; the
host records a rate-limited diagnostic and never echoes the secret.

### 4.2 `WELCOME` (type 2)

| Offset | Size | Field | Type | Constraint |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | `player` | `u8` | `1` Player 1, `2` Player 2; `0` when rejected |
| 1 | 1 | `session_state` | `u8` | `1` paired, `2` expired, `3` secret rejected, `4` full, `5` unsupported |
| 2 | 2 | `heartbeat_interval_ms` | `u16` | 100–5000 |
| 4 | 2 | `disconnect_timeout_ms` | `u16` | At least 2× heartbeat, at most 30000 |
| 6 | 2 | `reorder_window_packets` | `u16` | 0–64 |
| 8 | 8 | `host_monotonic_ns` | `u64` | Host send clock reading |
| 16 | 8 | `session_expires_unix_s` | `u64` | Wall-clock expiry for UI/rejoin policy |

The header contains the newly assigned nonzero controller ID. The wall-clock
expiry is never used for motion age or latency calculations.

For an authenticated or structurally valid join attempt that cannot be accepted,
the host sends a rejection-form `WELCOME` with `player = 0`, a `session_state`
from 2–5, and an ephemeral nonzero header controller ID. Rejection packets never
echo the pairing secret. This gives controllers an actionable error without
adding a second handshake message type; rejected IDs are not valid for motion.

### 4.3 `PING` (type 3)

| Offset | Size | Field | Type | Constraint |
| ---: | ---: | --- | --- | --- |
| 0 | 4 | `ping_id` | `u32` | Sender-chosen correlation ID |
| 4 | 4 | `reserved` | `u32` | `0` |
| 8 | 8 | `sender_monotonic_ns` | `u64` | Time immediately before send |

### 4.4 `PONG` (type 4)

| Offset | Size | Field | Type | Constraint |
| ---: | ---: | --- | --- | --- |
| 0 | 4 | `ping_id` | `u32` | Copied from `PING` |
| 4 | 4 | `reserved` | `u32` | `0` |
| 8 | 8 | `echo_sender_monotonic_ns` | `u64` | Copied exactly from `PING` |
| 16 | 8 | `receiver_receive_monotonic_ns` | `u64` | Receiver time after decode |
| 24 | 8 | `receiver_send_monotonic_ns` | `u64` | Receiver time immediately before send; ≥ receive |

The original sender combines these values with its receive timestamp using the
four-timestamp clock-offset calculation. A mismatched `ping_id` or echoed time
is ignored as an unsolicited `PONG`.

### 4.5 `MOTION` (type 5)

| Offset | Size | Field | Type | Units / constraint |
| ---: | ---: | --- | --- | --- |
| 0 | 8 | `sensor_monotonic_ns` | `u64` | Native sensor timestamp; > 0 |
| 8 | 4 | `accel_x` | `f32` | m/s²; finite, absolute value ≤ 200 |
| 12 | 4 | `accel_y` | `f32` | m/s²; finite, absolute value ≤ 200 |
| 16 | 4 | `accel_z` | `f32` | m/s²; finite, absolute value ≤ 200 |
| 20 | 4 | `gyro_x` | `f32` | rad/s; finite, absolute value ≤ 100 |
| 24 | 4 | `gyro_y` | `f32` | rad/s; finite, absolute value ≤ 100 |
| 28 | 4 | `gyro_z` | `f32` | rad/s; finite, absolute value ≤ 100 |
| 32 | 4 | `orientation_x` | `f32` | Quaternion component; finite |
| 36 | 4 | `orientation_y` | `f32` | Quaternion component; finite |
| 40 | 4 | `orientation_z` | `f32` | Quaternion component; finite |
| 44 | 4 | `orientation_w` | `f32` | Quaternion component; finite |
| 48 | 1 | `accuracy` | `u8` | `0` unreliable, `1` low, `2` medium, `3` high, `255` unknown |
| 49 | 1 | `sensor_flags` | `u8` flags | Defined below |
| 50 | 2 | `reserved` | `u16` | `0` |

The quaternion magnitude must be in `[0.98, 1.02]`; a zero or non-normalized
quaternion is invalid. Sensor flag bits are: bit 0 accelerometer valid, bit 1
gyroscope valid, bit 2 orientation valid, bit 3 synthetic/test sample and bit 4
controller calibration applied. Bits 0–2 must be set for live Release 1 motion;
bits 5–7 must be zero.

### 4.6 `CALIBRATION` (type 6)

| Offset | Size | Field | Type | Units / constraint |
| ---: | ---: | --- | --- | --- |
| 0 | 8 | `sensor_monotonic_ns` | `u64` | > 0 |
| 8 | 16 | `neutral_orientation_xyzw` | 4 × `f32` | Normalized quaternion |
| 24 | 12 | `accel_bias_xyz` | 3 × `f32` | m/s²; finite, each absolute value ≤ 50 |
| 36 | 12 | `gyro_bias_xyz` | 3 × `f32` | rad/s; finite, each absolute value ≤ 20 |
| 48 | 4 | `quality` | `f32` | Finite in `[0, 1]` |
| 52 | 1 | `result` | `u8` | `1` success, `2` failed |
| 53 | 3 | `reserved` | bytes | All zero |

The same quaternion normalization rule as `MOTION` applies even to a failed
result so corrupt sensor values cannot enter logs.

### 4.7 `STATUS` (type 7)

| Offset | Size | Field | Type | Constraint |
| ---: | ---: | --- | --- | --- |
| 0 | 8 | `sender_monotonic_ns` | `u64` | > 0 |
| 8 | 1 | `battery_percent` | `u8` | 0–100, or `255` unknown |
| 9 | 1 | `sensor_state` | `u8` | `0` unavailable, `1` ready, `2` streaming, `3` error |
| 10 | 1 | `app_state` | `u8` | `0` foreground, `1` background, `2` inactive |
| 11 | 1 | `pause_reason` | `u8` | `0` none, `1` user, `2` background, `3` network, `4` host, `5` safety |
| 12 | 2 | `actual_sample_hz` | `u16` | 0–1000; 0 when not sampling |
| 14 | 2 | `reserved` | `u16` | `0` |
| 16 | 4 | `last_motion_sequence` | `u32` | Last emitted/received motion sequence |

`pause_reason` must be zero unless the sender is paused or inactive. A host
`STATUS` uses battery `255` and reports the most recent motion sequence it has
accepted from the addressed controller.

### 4.8 `GOODBYE` (type 8)

| Offset | Size | Field | Type | Constraint |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | `reason` | `u8` | `1` user ended, `2` app terminating, `3` host shutdown, `4` protocol error, `5` session expired |
| 1 | 3 | `reserved` | bytes | All zero |
| 4 | 4 | `last_sequence` | `u32` | Last sequence sent before shutdown |
| 8 | 8 | `sender_monotonic_ns` | `u64` | > 0 |

## 5. Decoder validation order and rejection codes

Decoders validate in this order so all languages return the same primary error:

1. `TOO_SHORT`: fewer than 28 bytes.
2. `BAD_MAGIC`: magic is not `0x4D42`.
3. `UNSUPPORTED_VERSION`: protocol version is not 1.
4. `UNKNOWN_MESSAGE_TYPE`: type is outside 1–8.
5. `INVALID_FLAGS`: an unknown flag is set or flags are illegal for the type.
6. `INVALID_HEADER_LENGTH`: header length is not 28.
7. `INVALID_PAYLOAD_LENGTH`: declared, actual or type-specific size mismatch.
8. `NONZERO_RESERVED`: a required-zero header or payload field is nonzero.
9. `INVALID_SESSION_ID`: session ID is zero.
10. `INVALID_CONTROLLER_ID`: ID is zero for a non-`HELLO`, or nonzero for a
    `HELLO`.
11. `INVALID_UTF8`: a text field is empty, malformed, contains NUL or violates
    its declared bound.
12. `INVALID_ENUM`: an enum or unknown capability/sensor bit is invalid.
13. `NON_FINITE_FLOAT`: any float is NaN or infinity.
14. `INVALID_QUATERNION`: magnitude is outside `[0.98, 1.02]`.
15. `INVALID_VALUE`: any remaining numeric, timestamp or cross-field constraint
    fails.

A decoder returns one rejection code and no partially trusted message. It must
not throw across the network boundary or allocate from an unvalidated length.

## 6. Compatibility and runtime handling

- Version 1 decoders accept only version 1. A future version uses a new version
  number and its own complete header/payload rules; it is not guessed from
  lengths.
- A duplicate has the same sender, controller ID and sequence as a previously
  accepted logical message. Drop it and increment the duplicate metric.
- For motion, default `reorder_window_packets` is 8. A packet older than the
  newest accepted sequence by more than the negotiated window is dropped. A
  packet inside the window may be inserted by sensor timestamp if still fresh;
  the simulation never waits for missing packets.
- Motion age is `host_monotonic_now - (sensor_monotonic_ns + estimated_offset)`.
  Drop a sample when age exceeds the negotiated stale limit (initially 50 ms)
  or appears more than 20 ms in the future. Re-estimate offset after reconnect.
- Reliable control messages retry at most three times with 250, 500 and 1000 ms
  delays. `MOTION` is never retried or batched.
- Accept datagrams only from the endpoint bound by the successful pairing
  handshake. A valid session/controller ID from another endpoint is ignored and
  rate-limited in diagnostics.

## 7. Worked `MOTION` packet

This 80-byte example has session `0x0102030405060708`, controller
`0x0A0B0C0D`, sequence 42 and sensor time 123,456,789 ns. Acceleration is
`(1.0, 0.0, -9.80665)` m/s², angular velocity is `(0.1, -0.2, 3.5)` rad/s,
orientation is identity `(0, 0, 0, 1)`, accuracy is high and all three sensors
are valid.

| Datagram offset | Bytes | Meaning |
| ---: | --- | --- |
| 0 | `4d42` | Magic |
| 2 | `01` | Protocol v1 |
| 3 | `05` | `MOTION` |
| 4 | `0000` | Flags |
| 6 | `001c` | 28-byte header |
| 8 | `0034` | 52-byte payload |
| 10 | `0000` | Header reserved |
| 12 | `0102030405060708` | Session ID |
| 20 | `0a0b0c0d` | Controller ID |
| 24 | `0000002a` | Sequence 42 |
| 28 | `00000000075bcd15` | Sensor time 123,456,789 ns |
| 36 | `3f800000 00000000 c11ce80a` | Acceleration XYZ |
| 48 | `3dcccccd be4ccccd 40600000` | Gyroscope XYZ |
| 60 | `00000000 00000000 00000000 3f800000` | Quaternion XYZW |
| 76 | `03` | High accuracy |
