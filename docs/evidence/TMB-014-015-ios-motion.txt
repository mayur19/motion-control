The first physical run exposed three fixture-test failures because the tests
resolved protocol vectors through the Mac checkout path. The shared golden
vectors are now resources of the test bundle, so the same tests pass in both
the sandboxed device bundle and Simulator.

New motion-pipeline tests prove:
- the 256-entry sensor/network handoff uses an explicit drop-oldest policy;
- duplicate or backward native timestamps are rejected and counted;
- each accepted synthetic sample produces one independently decodable 80-byte
  protocol-v1 MOTION datagram with a unique sequence number.

Implementation inspection
-------------------------
- Core Motion requests 200 Hz and uses CMDeviceMotion.timestamp (monotonic).
- Acceleration is converted from g to m/s^2; gyro remains rad/s; axes are not
  remapped; quaternion order is protocol x/y/z/w.
- The Core Motion callback only normalizes data and offers it to a bounded,
  lock-protected buffer. UDP work runs on a dedicated dispatch queue.
- Foreground calibration/connected states start sampling. Leaving the active
  scene stops sampling and streaming, clears the queue and transitions the UI to
  Paused.
- The debug panel exposes destination, requested/actual Hz, queue depth, local
  drops, non-monotonic rejects, send count/rate, errors and last successful send.
- The UDP streamer emits one datagram per dequeued sample; it has no batching,
  retries or transport-level retransmission.

Real-device defects found and fixed during execution
----------------------------------------------------

- Swift 6 actor-executor inheritance caused traps when Core Motion and UDP
  callbacks ran on their intended worker queues; handlers are now constructed
  from nonisolated helpers.
- Pairing used the LAN destination while the separate motion socket retained
  the debug loopback destination; validated join host/port now feed both paths.
- The engineering host now drains samples after diagnostics/telemetry signals,
  preventing its not-yet-implemented gameplay queue from filling during soaks.
- Foreground resume restores Connected state and restarts sampling/streaming.

Foreground/background behavior was physically observed: backgrounding sent an
immediate Paused status, stopped MOTION traffic and produced a host timeout.
Resume clock/port gating is covered by the real-UDP integration test; the full
iPhone Wi-Fi-off/restore matrix remains part of TMB-021 physical evidence.
